Generador de transacciones Bitcoin

Construye una transacción Bitcoin paso a paso. Empezamos seleccionando un UTXO P2WPKH (bc1q) que queremos gastar.

PASO 1: SELECCIONAR UTXO

Elegir el UTXO que vamos a gastar

Una transacción Bitcoin no empieza indicando simplemente una cantidad. Primero debemos elegir una salida no gastada (UTXO) de una transacción anterior. Para identificarla necesitamos su TXID y el índice de salida (vout).

El TXID y el vout se enviarán a mempool.space para verificarlos (la dirección de destino y las claves nunca se envían).

¿QUÉ ACABAMOS DE SELECCIONAR?

De output anterior a input nuevo

La transacción anterior creó una salida con una cantidad de satoshis y una condición de gasto. Mientras esa salida no se haya gastado, es un UTXO. Nuestra nueva transacción hará referencia a ese UTXO mediante TXID + vout.

TRANSACCIÓN ANTERIOR │ └── OUTPUT #0 │ ├── VALUE │ └── 0 sats │ └── SCRIPT PUBKEY └── → UTXO │ ▼ gastar NUEVA TRANSACCIÓN │ └── INPUT #0

Nos centramos en direcciones bc1q, y aceptamos únicamente outputs P2WPKH / SegWit nativo.

El sobrante es inferior al umbral de dust configurado (294 sats, correspondiente a la política estándar de Bitcoin Core a 3 sat/vB), así que no se genera salida de cambio: todo el sobrante pasa a formar parte de la comisión.

El tamaño se estima para 1 input P2WPKH firmado (≈68 vB) más el overhead de la transacción (≈10,5 vB) y 1 o 2 salidas P2WPKH (≈31 vB cada una), siguiendo la fórmula estándar de tamaño virtual (vsize) de Bitcoin.

PASO 6: CALCULAR EL SIGHASH (BIP143)

El mensaje que se va a firmar

En una transacción SegWit no se firma el hexadecimal completo, sino un resumen (sighash) definido en el BIP143. Este resumen compromete los inputs, los outputs, el valor del UTXO que se gasta y el scriptCode, de modo que la firma no puede reutilizarse para otra transacción. Aquí calculamos ese resumen con SIGHASH_ALL; en el siguiente paso se firmará con la clave privada.

PASO 7: FIRMAR Y CONSTRUIR EL WITNESS

Firmar el sighash con la clave privada

Se firma el sighash con ECDSA (secp256k1, nonce determinista RFC 6979, s bajo), se codifica la firma en DER + 01 (SIGHASH_ALL) y se construye el witness [firma, clave pública]. La clave privada puede indicarse en formato WIF (el que exportan las carteras) o en hex (los 32 bytes en bruto). Se usa solo en tu navegador y no se envía ni se guarda.
